Topology

Roles · State · Channel
TOPOLOGY

Picking up from the Domain map — we now examine the controller–agent topology that every pipeline, agent, and credential later plugs into.

01 / The Three Parts

  • Controller — holds config (JENKINS_HOME), queue, history, UI/API, credentials. Runs no builds in production.
  • Agent — a machine offering executors: numbered slots, one build each.
  • Remoting — the channel shipping work out. Inbound = agent dials out (survives NAT); SSH = controller dials in (flat networks).

02 / What Lives in JENKINS_HOME

PathHolds
jobs/Job configs + build history
workspace/Checked-out code (rebuildable, deletable)
credentials.xml + secrets/Encrypted secrets — back up securely
config.xmlGlobal configuration

05 / Failure Modes

  • Disk fills with old builds → UI freezes; fix with build discarders + log rotation.
  • Everything pinned to built-in node → single contention point; fix with labeled agents.

A: Controller schedules, serves, stores. Agents execute — nothing else.

Wiring

Connection · Trust · Next

03 / Connection & Trust

  • Inbound — agent dials out via WebSocket; survives NAT, needs port 50000.
  • SSH — controller dials in; simple on flat networks, needs port 22 + credential.
  • Ephemeral wins — pristine container per run kills "works on my machine" and tool drift.

TRUST BOUNDARY

Never run untrusted fork PRs on permanent agents holding deploy credentials. Forks get isolated, credential-free agents — a malicious workflow otherwise owns your box.

  • Label typo → queue forever; check Executor Status.
  • Too many executors per CPU → starvation.

Bindings

Inject · Mask · Rotate

02 / Binding in Practice

withCredentials([usernamePassword(   credentialsId: 'registry-creds',   usernameVariable: 'U', passwordVariable: 'P')]) {   sh 'echo "$P" | docker login registry -u "$U" --password-stdin' } # Jenkins masks $U/$P in console output automatically

03 / Failure Modes

  • Secret echoed or baked into an image layer → treat as compromised, rotate immediately.
  • Wrong scope (System-only in pipeline) → "credentials not found"; move to Global.
  • Duplicate IDs → ambiguous resolution; keep IDs unique (github-acme-app-token).

LEAK = ROTATE

Masking is a backstop, not a guarantee. Any secret that touched a log, layer, or chat is compromised — replace by ID, zero Jenkinsfile changes.

Discipline

Pin · Stage · Failures

02 / Pin & Stage Upgrades

# plugins.txt — pinned, version-controlled git:5.2.1 workflow-aggregator:596.v8c21c963d92d credentials-binding:681.v346b_f30f5d80 docker-workflow:572.v950f58993843
RULES — upgrade in a staging Jenkins first (plugin updates, not core, cause most outages) · remove unused plugins (attack surface + startup + conflicts).

03 / Failure Modes

  • Update-all Friday → Monday outage; update deliberately with a snapshot.
  • No such DSL method → owning plugin not installed.
  • Core/plugin skew → cryptic startup failures; keep LTS + compatible set.

FRIDAY RULE

Never bulk-update plugins before a weekend. Deliberate upgrades with a rollback snapshot, or Monday owns you.

03 / Multibranch = PR Gates

Multibranch scans the repo, builds each branch/PR Jenkinsfile independently, reports status to GitHub checks. Branch deleted → job auto-removed. No hand-wired jobs per branch, ever.

  • 403/404 → wrong URL (trailing slash matters) or missing plugin.
  • Not triggering → trigger checkbox off; check Hook Log.
  • Duplicates → webhook + polling both on; disable polling.
  • Validate webhook secrets — or anyone curls your builds.

Trust

Agents · Secrets · Updates

02 / Agent-to-Controller Distrust

  • Builds execute attacker-influenced code — default deny on Agent → Controller access.
  • Ephemeral agents: a compromised container dies with the build.
  • Fork PRs → isolated, credential-free agents. Never shared permanent ones.

03 / Secrets & Updates

  • Secrets only via bindings; set +x around manual handling; TLS-only admin.
  • Rotate by ID replacement; deprovision SSO, don't rely on memory.
  • CVEs cluster in plugins: staging validates → snapshot → production.

IF SECRETS LEAK

JENKINS_HOME/secrets decrypts the whole store. Its exposure = everything is compromised. Rotate all of it.

Q: Why are PR builds a trust boundary?
A: PR contents are attacker-influenced code running on your agents — isolate execution and scope credentials.

As Code

JCasC · Backup · Console

03 / Controller From YAML

# jenkins.yaml — identical controller every boot jenkins: { numExecutors: 0 } credentials: { system: { … registry-token: "${REGISTRY_TOKEN}" } } # boot: pinned image + plugins.txt + jenkins.yaml. UI drift is ephemeral.

04 / Backup, Console, Tuning

  • Backup JENKINS_HOME minus workspaces; restore jobs + credentials + config + YAML + plugins. Untested backup = rumor. Encrypt off-site.
  • Script Console = Groovy as admin; audit every run; never paste blind snippets.
  • Queue — executors ≤ ~1 per 1–2 cores; heap ≥ 4 GB (-Xmx4g); stagger cron (H 9 * * *); quiet periods batch rapid commits.
PROD TOPOLOGY — active-passive controllers from one jenkins.yaml + replicated storage · agent fleets per team/env (labels route) · controller private behind TLS proxy, agents outbound-only · quarterly DR restore drill measured against RTO.

Logs & Recovery

Reading · Sandbox · Restore

02 / Reading a Build Log

  • First red line = effect; scroll up for the cause (exit code, Groovy stack).
  • Replay button re-runs edited pipelines without pushing commits.
  • Wipe workspace + rebuild separates dirty-workspace flakes from real failures.

03 / Sandbox & Recovery

SANDBOX — untrusted scripts run allowlisted only; beyond that needs Script Approval. Prefer allowlisted steps — each approval is future maintenance.
RECOVERY — bad config? Restore config.xml + Reload Configuration (no restart). Disaster? Restore JENKINS_HOME backup to a fresh pinned image, replay the smoke pipeline.
